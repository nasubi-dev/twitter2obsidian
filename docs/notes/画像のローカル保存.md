# 画像のローカル保存（ポスト削除で画像が消える問題）

2026-10-06 に検討・実装した。

- 既存ノートの取り込み: `scripts/localize-images.mjs` を 2026-10-06 に実行済み。ノート 498 件、画像 728 枚（動画サムネイルを含む）のうち 668 枚・172MB を保存、60 枚は消失していた（消えた画像を含むノートは 47 件、`images_lost: true` で絞り込める）
- 拡張: 保存時に画像も vault に書き込むよう `background.js` を改修
- git: vault の `.gitignore` に `assets/twitter/` を追加（画像を置く前に入れた）
- バックアップ: `~/.claude/scripts/obsidian-assets-backup.sh` が vault の `assets/` を `gdrive:obsidian/assets` へ 1 時間ごとにコピー（launchd `com.k24083kk.obsidian-assets-backup`）

## 問題

保存したノートの画像は `pbs.twimg.com` の URL を直接表示しているだけで、vault には画像の実体がない。元のポストが削除されたり、アカウントが凍結・非公開になったりすると、ノートの文章は残るが画像は表示されなくなる。

2026-10-06 時点の vault:

- `Clippings/twitter/` に 842 件。frontmatter に `images:` があるのは 498 件、ユニークな画像 URL は 695 個
- 695 個すべてを取得してみると、59 個（404 が 53、403 が 6）が取得できなかった。**8.5% はすでに見られない**（最初に無作為の 80 個で試したときは 12%）
- Base（`base/twitter.base`）のカード表示は `note.images` を画像に使っているので、そこも欠ける

消えた画像は後から取り戻せないので、生きているうちに手元へ取り込む。

## 方針

2 本立てにする。

1. **バックフィル（急ぎ）**：既存ノートの画像を一括でダウンロードし、ノートの参照をローカルに書き換えるスクリプト。放っておくほど消える画像が増えるので、こちらを先にやる
2. **保存時の取り込み**：拡張でポストを保存するとき、画像も一緒に vault へ書き込む。以後のノートは最初からローカル参照になる

### 保存先と名前

- `assets/twitter/<メディアID>.webp`。メディア ID は画像 URL の最後の部分（`pbs.twimg.com/media/HQ9drvuboAAgvjf` なら `HQ9drvuboAAgvjf`）。動画サムネイル（`ext_tw_video_thumb` など）も同じ規則
- 当初はポスト ID + 連番にするつもりだったが、メディア ID の方が単純で、引用元・引用先の両方のノートに同じ画像が出ても 1 ファイルで済むので変えた。何度実行しても同じ名前になる

### 形式とサイズ（2026-10-06 計測）

`pbs.twimg.com/media/<id>?format=<形式>&name=<サイズ>` で取得する。`format=webp` で webp が直接返る（`content-type: image/webp`）ので、変換処理は要らない。`name=orig` は webp では返らなかった。

今ある画像 695 個を全部 `webp` / `large` で取得:

- 取得できた 636 個（91.5%）の合計は **169MB**。1 枚あたり平均 272KB、中央値 196KB、上位 5% は 768KB 以上、最大 1.5MB
- 消えていたのは 59 個（404 が 53、403 が 6）。8.5% にあたる

サイズ違いの比較（同じ 44 個を抽出、取得できたものの平均）:

| 指定 | 平均 | 備考 |
|---|---|---|
| webp / large | 262KB | 長辺 2048px |
| webp / medium | 131KB | 長辺 1200px 前後。large の半分 |
| webp / small | 52KB | 文字の多い画像は読めなくなる |
| jpg / large | 339KB | 今のノートが参照している形式 |
| jpg / medium | 167KB | |

### 増えるペース

frontmatter の `created` で数えると、2025-11〜2026-08 の 10 か月で、ノートの画像は 368 個増えた。**月に平均約 37 個**（少ない月で 17、多い月で 53）。

| 画像の数 | large（272KB） | medium（約 136KB） | このペースで到達する時期 |
|---|---|---|---|
| 636（今ある分） | 169MB | 85MB | バックフィル直後 |
| 1,000 | 266MB | 133MB | 約 10 か月後（2027 年夏） |
| 2,000 | 531MB | 266MB | 約 3 年後 |
| 5,000 | 1.3GB | 664MB | 約 10 年後 |
| 10,000 | 2.6GB | 1.3GB | ブックマーク一括保存を多用した場合 |

増え方は large で月約 10MB（年約 120MB）、medium で月約 5MB（年約 60MB）。ブックマークの一括保存をすると、この表より一気に進む。

### git に入れない

vault のリポジトリ（GitHub の `nasubi-dev/obsidian`、obsidian-git が 1 時間ごとに自動コミット）は、2026-10-06 時点で `.git` がすでに **1.0GB** ある。

- 今も追跡しているファイルの分は 179MB しかない。残りは削除・変換済みのファイルが履歴に残った分で、`Reading List/`（削除済み）が 459MB、`assets/` が 527MB を占めている。拡張子別では jpg 401MB、png 270MB
- git では、一度コミットした画像はファイルを消しても履歴から減らない。webp は差分圧縮も効かないので、入れた分だけそのまま増え続ける
- GitHub が推奨するリポジトリサイズの目安（1GB 程度）をすでに超えている

なので、画像は git に入れない。

- `assets/twitter/` を vault の `.gitignore` に入れる。**最初の画像を置く前に入れておく**。後からだと、自動コミットで 1 度でも入った分が履歴に残る
- バックアップは git とは別に取る。この Mac は Time Machine が未設定なので Google Drive を使う。`~/.claude` のバックアップ（`claude-backup.sh`）と同じく rclone の `gdrive:` リモートに送る。Drive には vault の `assets/` だけを `obsidian/assets/` として置く（ノートは git にあるので送らない）
- Drive は vault の `assets/` をそのまま写す（`rclone sync`）。vault で消したファイルは Drive からも消える。画像が必要かどうかは、ノートから参照されているかで判断する
	- 2026-10-06 に、消したファイルを `assets-deleted/<日付>/` に 30 日残す仕組みも作ったが、仕組みを複雑にするだけなのでやめた
	- 共有画像が巻き添えで消えた場合も、元のポストが残っていれば `localize-images.mjs --apply` で取り直せる（ノートの `image_urls` を見てファイルが無い画像を再取得する）
- 1 回で消せるのは 200 件まで（`--max-delete`）。vault が移動・空になったときに Drive まで全消しにしないため
- 復元は `obsidian-assets-backup.sh --restore`
- git の外に出せば容量はほぼ気にならない（10 年分でも 1〜2GB）。文字の多い画像（スライドや漫画のスクショ）が読めるように、**large を採用**した

既存の 1.0GB の履歴を軽くする（`git filter-repo` で `Reading List/` などを履歴から消し、force push する）ことも可能だが、この件とは別の作業として扱う。

### ノートの書き換え

- frontmatter の `images:` / `quoted_images:` をローカルのリンク（`"[[assets/twitter/<メディアID>.webp]]"`）に置き換える
- 元の URL は `image_urls:` / `quoted_image_urls:` に移して残す（出典として、また再取得用に）
- 本文の `![...](https://pbs.twimg.com/...)` は `![[assets/twitter/<メディアID>.webp]]` に置き換える
- 要確認：Bases のカード表示が、プロパティに入ったリンクの画像を表示できるか。表示できなければ `images:` は URL のまま残し、`local_images:` を別に足して `base/twitter.base` の `image:` をそちらに向ける

## 1. バックフィルスクリプト

`scripts/patch-quotes.mjs` と同じく、vault のフォルダを直接読み書きする Node スクリプト（`scripts/localize-images.mjs`）にする。Obsidian が起動していなくても動く。

1. `Clippings/twitter/*.md` を走査し、frontmatter と本文から `pbs.twimg.com` の画像 URL（`media/` と動画サムネイル）を集める
2. 各 URL を `format=webp&name=large` に正規化してダウンロードし、`assets/twitter/` に置く。すでにファイルがあれば飛ばす
3. 取得に成功した画像だけ、ノートの参照を書き換える
4. 404 / 403 の画像は元の URL のまま残し、frontmatter に `images_lost: true` を付ける。Base で欠けたノートを一覧できるようにするため
5. 最後に「取得数・スキップ数・消失数・消失したノートの一覧」を出す

運用上の注意:

- 連続アクセスを避けるため、並列数を 2〜4 程度に絞り、間隔を空ける
- 最初に `--dry-run` で、件数と書き換え内容だけを出せるようにする
- vault の update-time-on-edit プラグインは、Obsidian で開いているノートにしか反応しない。実行中は Obsidian を閉じておくのが無難
- 消えた画像を Internet Archive から救えるかは未確認。2026-10-06 に `archive.org/wayback/available` を試したが、JSON 以外の応答が返ってきて判定できなかった。救えるなら手順 4 の前に試す

## 2. 拡張の改修

保存の流れ（`background.js` の保存処理）に画像の取り込みを足す。

1. `manifest.json` の `permissions` に `https://pbs.twimg.com/*` を追加する。background から CORS に邪魔されずに取得するため
2. Markdown を PUT する前に、各画像を `format=webp&name=large` で `fetch` し、Blob のまま Local REST API に `PUT /vault/assets/twitter/<メディアID>.webp`（`Content-Type: image/webp`）で書き込む
3. 書き込めた画像はローカル参照で、失敗した画像は従来どおり URL で `generateMarkdown` に渡す。**画像の失敗でノートの保存は止めない**
4. 引用元の画像も同じように扱う

ブックマーク一括保存でも同じ処理を通るので、件数が多いときの間隔は 1 と同じ考え方で調整する。

## やらないこと（今回）

- **動画**：今は動画のサムネイルだけを画像として保存している。動画本体も消えるが、容量が桁違いなので見送る。必要になったら、埋め込み表示用の公開 API（`cdn.syndication.twimg.com/tweet-result`）の `video_info` から mp4 を取る（Atlas がこの方法で取得している）
- **Atlas に画像を預ける案**：git は膨らまないが、Obsidian の Base から画像が見えなくなるので採らない
- **削除の検知**：画像を手元に置いてしまえば、ポストが消えたかどうかを追う必要はない
